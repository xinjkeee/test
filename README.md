# AI-помощник для подготовки товарных описаний

Локальный MVP-сервис для генерации черновика B2B-карточки контрольно-измерительного прибора. Сервис принимает JSON, отправляет его в LLM через OpenAI-compatible API и возвращает структурированный JSON или Markdown.

## Возможности

- FastAPI API и Swagger UI;
- CLI для генерации из JSON-файла;
- SEO-заголовок до 70 символов;
- SEO-описание 800–1200 символов;
- характеристики, поисковые запросы и commercial-блок;
- явное отображение отсутствующих данных;
- запрет на добавление технических фактов из внешних знаний;
- поствалидация значений характеристик и числовых значений;
- один автоматический retry при нарушении формата или правил;
- понятная обработка ошибок входного JSON и LLM API.

## Требования

- Python 3.11 или новее;
- API-ключ выбранного OpenAI-compatible провайдера.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Заполните `LLM_API_KEY` в `.env`. Для другого совместимого провайдера измените `LLM_BASE_URL` и `LLM_MODEL`.

## Запуск API

```bash
uvicorn app.main:app --reload
```

После запуска:

- Swagger UI: <http://127.0.0.1:8000/docs>;
- проверка состояния: <http://127.0.0.1:8000/health>.

### JSON API

```bash
curl -X POST http://127.0.0.1:8000/api/v1/generate \
  -H 'Content-Type: application/json' \
  --data @examples/product_1.json
```

### Markdown API

```bash
curl -X POST http://127.0.0.1:8000/api/v1/generate/markdown \
  -H 'Content-Type: application/json' \
  --data @examples/product_1.json
```

## CLI

```bash
python -m app.cli examples/product_1.json --format json
python -m app.cli examples/product_1.json --format markdown
```

## Формат ответа

```json
{
  "seo_title": "...",
  "seo_description": "...",
  "characteristics": [
    {
      "name": "диапазон измерений",
      "value": "0–1,6 МПа",
      "source": "input"
    }
  ],
  "search_queries": ["...", "...", "..."],
  "commercial_block": {
    "target_audience": "...",
    "solves_tasks": ["..."]
  },
  "missing_data": [],
  "warnings": []
}
```

`source` показывает происхождение характеристики. В рабочем результате приложение пересобирает список характеристик из проверенного входного JSON, поэтому модель не может подменить значение. `missing_data` дополняется приложением для пустых производителя, описания или `specs`.

## Архитектура

- `app/models` — контракты входа и выхода и нормализация данных;
- `app/services/llm_client.py` — изолированный HTTP-клиент OpenAI-compatible API;
- `app/services/prompt_builder.py` — системный и пользовательский промпты;
- `app/services/validator.py` — ограничения SEO, проверка характеристик и числовых фактов;
- `app/services/generator.py` — orchestration и retry;
- `app/api/routes.py` — HTTP endpoints;
- `app/cli.py` — запуск из файла;
- `examples` — два демонстрационных товара, включая неполные данные.

## Принятые решения

LLM получает только JSON товара и обязана вернуть структурированный JSON. Температура установлена в `0.2`, чтобы уменьшить вариативность. В промпте явно запрещены внешние знания и выдуманные технические параметры.

Одного промпта недостаточно для защиты от галлюцинаций, поэтому после ответа выполняются проверки:

1. валидируется схема ответа;
2. проверяется длина SEO-полей;
3. проверяется наличие всех исходных характеристик;
4. значения характеристик сравниваются с входными дословно;
5. числовые токены в сгенерированном тексте сравниваются с числами из входных данных;
6. при ошибке выполняется один retry с описанием проблемы;
7. после успешной проверки список характеристик пересобирается из входа.

## Тесты

```bash
pytest
ruff check .
```

Тесты не вызывают реальный LLM API: они проверяют нормализацию входных данных, бизнес-валидацию, защиту от неизвестных характеристик и API-ошибки.

## Ограничения

- сервис не сверяет данные с внешними каталогами или паспортами;
- числовая проверка консервативна и не заменяет техническую экспертизу;
- качество маркетингового текста зависит от выбранной модели;
- при слишком бедном входе модель может не суметь естественно заполнить 800–1200 символов — такой ответ будет отклонён и после retry вернётся ошибка;
- нет базы данных, авторизации, истории версий и массового импорта;
- результат является черновиком и должен быть проверен контент-менеджером.
